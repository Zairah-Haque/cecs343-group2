# Contributing

## 1. Branches
Format: 
	Branches
	
	Biltz-Coordinator
	Ivanluu005-license
	Sangthian-SECURITY
	Zairah--Documentation-and-Log
	
Nobody commits directly to `main`. All work happens on a branch.

## 2. Commits
Message under 50 characters, written in present tense, states what and why.
Bad: `fixed stuff`
Good: `Fix null check in parseInput() — was crashing on empty string`

## 3. Pull Requests
PR description must answer three things:
- **What** changed
- **Why** it changed
- **How to check it** — steps or commands the reviewer runs to verify it works

## 4. Review
One approval required from a teammate before merge. You cannot approve your own PR.
Reviewer leaves at least one inline line comment (not just "LGTM").

## 5. Merging
Only the PR author merges, and only after receiving approval.
Delete the branch immediately after merging.
