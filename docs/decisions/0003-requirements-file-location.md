Decision: Keep requirements.md in docs/ so the project requirements have their own file in the documentation folder.

Rejected alternatives:
- Put requirements.md at the repository root. This was the alternative named in Prompt D; the requirements would then sit beside the README and team guidance files.
- Put the requirements directly in README.md. The README already introduces the project, but combining the requirements with it would make the file serve both purposes.
Costs: Readers need to open docs/ to find the requirements instead of seeing them at the repository root.
